The companion to the spco.ca SEO baseline audit of 20 November 2026. That document records the site as it was crawled; this one records what was changed and re-measures the figures. Every page was fetched and parsed, every link and image requested, the rendered pages compared element by element against copies saved before any change, and an on-page audit and Lighthouse run repeated on the live site. Where a baseline issue had already been fixed by someone else before this work began, it is reported as such.

01 — Executive summary

The spam is gone, the crawl path is clean, and every page reads in order.

When we re-checked the site before starting, the critical noindex block from the baseline had already been lifted: all five public pages returned index, follow with a self-referencing canonical. That fix was made by someone else between the crawl and our work, and we do not claim it.

Re-checking also surfaced a more serious problem the baseline export could not see. The server was still publishing a spam sitemap left by a 2022 hack: spco.ca/sitemap/sitemap.xml and 12 more files (about 24 MB) listing German product-spam URLs on the firm's domain, generated by a script folder /contactq/. Both are now backed up privately and removed. The robots.txt file asked crawlers to wait ten seconds between pages and named no sitemap; it now declares the real sitemap. Heading levels no longer skip on any page, the site serves pages from cache, and nothing a visitor sees changed.

What changed in this round
  • robots.txt declares the sitemap and the crawl delay is gone. The original was a physical hosting-panel file (# hestiacp autogenerated); it was backed up before replacement.
  • The 2022 spam sitemap is removed. /sitemap/ and /contactq/ now return 404.
  • The XML sitemap lists only real pages. 5 URLs. The empty client-resource page is marked noindex and dropped from it.
  • Heading levels descend in order on every page. 36 tag changes across 4 pages and the footer; a small stylesheet keeps each changed element looking exactly as before.
  • Pages are cached. LiteSpeed Cache installed on a LiteSpeed server that had none, with page caching only and every optimisation that can break Elementor left off.
  • Duplicate stylesheets stopped. Five copies of icon and menu files that a plugin loaded on top of Elementor's own.
  • Images and phone links corrected. 3 images that rendered with empty alt text now carry the description the designer wrote; both phone links now use the standard tel:+17057370983.

How the look was kept
A heading tag change normally changes its size. Here it didn't.

The theme sizes headings by tag, at its own breakpoints (921 px and 544 px), so moving an H4 to H3 would have made it larger. Before touching the live site, we simulated every change on copies of the pages and measured what would move. We then wrote a small stylesheet, spco-heading-preserve.css, that holds each changed element at its original values for every screen size, and proved offline that the result matched. After going live we measured again: identical.

09 — URL & canonical analysis

No URL was changed.

Permalinks, page slugs and the resource URL base are untouched. All five public pages carry a self-referencing canonical. http:// and http://www. both 301 to https://spco.ca/, and a missing trailing slash 301s to the slashed URL.

One host only: https://www.spco.ca/ used to answer 200, which made the whole site reachable at two addresses. It now 301-redirects to https://spco.ca/, keeping the page path and any query string (for example www.spco.ca/about/?x=1 → spco.ca/about/?x=1). The rule sits at the top of .htaccess, and the original file was backed up first.

16 — How the site was protected

Nothing a visitor sees was changed.

Structure and styling compared element by element, on all six pages, at five screen widths.

  • Backups first. A full database export (172 MB) and an archive of the spam folders, child theme, robots.txt and .htaccess were saved outside the web root and checked before any change.
  • Rendered copies of every page were saved before any change, then re-fetched after and rendered at 1280, 1000, 800, 600 and 390 px. Font, size, weight, line height, colour, spacing and box size were compared for every element.
  • Result: identical, except the footer logo box, which is under 1 px taller because the smaller image file has a very slightly different aspect ratio.
  • Link counts, image counts and Elementor element counts identical on all 6 pages. All 45 icons render the same glyph and font after the duplicate stylesheets were removed.
  • Screenshots at desktop, tablet and phone checked: hero, cards, reviews carousel, contact form (Gravity Forms renders), embedded map and footer.
  • The child-theme code was syntax-checked with php -l on the server before going live. Zero PHP errors in any page; the server error log shows nothing from these changes.
  • No URL, menu, page copy, title or description was changed. Permalinks were not touched.
Disclosed in full
Someone else changed the site at the same time

During the work, Migrate Guru and WP Mail Logging were removed, Elementor Pro was updated to 4.4.1 and WordPress debug mode was turned off. None of these were our actions. Page edit history shows only our changes to the pages themselves, and our before/after comparison passed with those changes in place. Whoever made them should confirm they were intended, especially removing WP Mail Logging, which recorded outgoing form emails.
